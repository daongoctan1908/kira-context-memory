# T10.1 — Local product Compose stack

## Scope

`compose.product.yaml` is the disposable laptop acceptance environment for the product path. It
uses the real application-managed auth, conversation API, Worker, Mem0 integration and production
frontend image. The only substitutes are four explicit, deterministic provider mocks:

| Service | Replaces | Local port |
|---|---|---:|
| `mock-kira` | KiRa auth and SSE API | 18212 |
| `mock-rewriter` | OpenAI-compatible rewrite model | 18213 |
| `mock-embedding` | OpenAI-compatible embedding model | 18214 |
| `mock-memory-llm` | OpenAI-compatible formation model | 18215 |

No external provider is contacted. The fixed database and provider credentials are synthetic,
loopback-only values. They are not production defaults.

The startup graph is deliberately ordered:

```text
PostgreSQL healthy
  → migration
  → auth-init + memory-init
  → provider mocks healthy
  → Gateway + Worker healthy
  → frontend healthy
```

`auth-init` is idempotent. It creates the local operator on a fresh volume and resets that same
operator's password on an existing volume so a stale local password cannot make the smoke
irreproducible.

## Run the product acceptance

From the repository root:

```powershell
docker compose -f compose.product.yaml config --quiet
docker compose -f compose.product.yaml up -d --build --wait
docker compose -f compose.product.yaml ps -a
uv run python -m scripts.smoke_product_stack
```

Open `http://127.0.0.1:18080` and sign in with the disposable defaults:

```text
username: local-admin
password: local-product-only
```

Override them before `up` and before running the smoke when desired:

```powershell
$env:PRODUCT_ADMIN_USERNAME="local-operator"
$env:PRODUCT_ADMIN_PASSWORD="another-local-password"
```

The smoke goes through the frontend's same-origin Nginx proxy and proves:

1. product login and CSRF cookies work;
2. a conversation turn returns before blocked memory formation finishes;
3. Worker commits the extracted fact;
4. a second conversation owned by the same user retrieves that fact;
5. the rewrite output, rather than the raw follow-up, reaches KiRa;
6. authenticated conversation listing sees both conversations.

Test controls and evidence expose hashes/counters only. The script prints sanitized PASS lines and
deletes its two synthetic conversations through the product deletion API in cleanup.

Stop while retaining the local database, or remove the disposable database too:

```powershell
docker compose -f compose.product.yaml down
docker compose -f compose.product.yaml down -v
```

## Optional observability

Observability is not in the product stack's readiness graph. Add the existing overlay only when
needed:

```powershell
docker compose -f compose.product.yaml -f compose.observability.yaml up -d --build --wait
```

This starts the OTel Collector. Prometheus and Grafana remain off. Start them independently with
`--profile metrics` only for metric/dashboard work. A Collector outage remains fail-open and does
not change Gateway or Worker readiness.

## Port overrides

All published ports bind to loopback and can be overridden with `PRODUCT_*_PORT` environment
variables. If `PRODUCT_FRONTEND_PORT` changes, Compose also derives `AUTH_ALLOWED_ORIGIN` from the
same value. Pass matching URL arguments to `scripts.smoke_product_stack` for any overridden
frontend, Gateway, Worker or mock port.
