# T10.3 — Continuous integration gate

## Scope

`.github/workflows/ci.yml` is the minimum pull-request gate for the product repository. It validates
code, database contracts, the offline benchmark harness, frontend behavior and the two product
images without contacting KiRa, OpenAI or an internal model endpoint.

The workflow runs on pull requests, pushes to `main` and manual dispatch. It has read-only
repository permission, cancels an older run for the same ref and contains three jobs:

| Job | Gate |
|---|---|
| `backend` | Ruff lint/format, canonical dataset validation, deterministic mock harness, full pytest suite, real PostgreSQL/pgvector integration and backend coverage ≥90%. |
| `frontend` | Locked pnpm install, ESLint, TypeScript, Vitest, production build and Chromium Playwright smoke. |
| `product-e2e` | Builds the backend and frontend production images through `compose.product.yaml`, starts only explicit provider mocks and runs T10.2. |

`product-e2e` starts only after backend and frontend pass. Its `always()` cleanup removes containers,
networks and the disposable PostgreSQL volume after both success and failure.

## Provider and benchmark boundary

CI explicitly sets `RUN_MEMORY_POLICY_EVAL=0` and `RUN_CROSS_SESSION_EVAL=0`. It does not define
provider URLs or credentials and never invokes `run_week5_benchmark`. The dataset step only:

1. validates the frozen cross-file contract;
2. compiles deterministic cases;
3. runs the mock dependency preflight;
4. emits `quality_claim=false` evidence under the runner's temporary directory.

Official semantic quality remains a PC/Kubernetes activity with approved KiRa/internal providers.
Langfuse and OTel are not scorers. T10.2 starts the local Collector only to prove fail-open behavior.

## Reproduce locally

Backend and offline harness:

```powershell
uv sync --frozen --all-extras
uv run ruff check .
uv run ruff format --check .
uv run python -m scripts.validate_dataset dataset/kira_ltm_v1 --json
uv run python -m scripts.week5_mock_acceptance --output artifacts/ci-mock-acceptance
$env:POSTGRES_TEST_URL = "postgresql+asyncpg://kira:local-product-only@127.0.0.1:15434/kira_ci"
uv run pytest
Remove-Item Env:POSTGRES_TEST_URL
```

Use a disposable database for `POSTGRES_TEST_URL`; the PostgreSQL integration fixtures mutate and
reset schema state.

Frontend:

```powershell
Set-Location frontend
corepack enable
corepack prepare pnpm@10.17.1 --activate
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
Set-Location ..
```

Product image/E2E gate:

```powershell
docker compose -f compose.product.yaml config --quiet
docker compose -f compose.product.yaml up -d --build --wait
uv run python -m scripts.smoke_product_e2e
docker compose -f compose.product.yaml -f compose.observability.yaml down -v --remove-orphans
```

The workflow is a regression gate, not release publishing: it builds local images but does not push
them to a registry or produce a promotion decision.
